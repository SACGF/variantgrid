{% page_help_embedded title="Annotation Run" %}

Runs are dispatched and reclaimed automatically - a run whose worker dies or stalls is re-launched, up to {% settings_value 'ANNOTATION_MAX_RUN_ATTEMPTS' %} attempts, before it is marked Error. The buttons are for a run in Error. Read Error Exception and Pipeline StdErr below first: a VEP version mismatch or a wrong setting fails again on every retry until it is fixed.

Retry Annotation
Deletes any annotation this run had partly imported and resets it to Created, so it is counted, dumped and annotated again from scratch. Use after fixing the cause of an error, or for a one-off failure (a worker restart, a full disk).
Retry Annotation (upload only)
Keeps the annotated VCF and repeats only the database import, after deleting any rows already imported. Use when annotation completed but the import failed. It needs the annotated VCF still on disk - that is removed once a run imports successfully - otherwise use Retry Annotation.
Subdivide AnnotationRun
Splits the range lock in half and replaces this run with one run per half. Use when a run keeps failing from running out of memory or time; subdivide a half again if it still fails. Every run on this range, of any pipeline type, is replaced - the scheduler recreates the other types for both halves. Offered for ranges spanning at least 1,000 variant IDs.
Make Local (annotate locally)
For a run awaiting external annotation: drops the external dump and returns the run to the local pipeline, so it is annotated on this server. Use when the external result is not coming back, or the run is too small to be worth the round trip. An annotated VCF for this run from the external machine will no longer import.
