Sorting and filtering composite columns

Header sort menu do this

Default key per composite: Sample → zygosity; Consequence → impact; Classifications → internal germline max; Predictions → damaging count. The ▾ lists the others. Nothing new is fetched — the underlying values are already in the row for the renderer.

Raw columns stay available and this

samples_allele_frequency, gnomad_af, impact… remain ordinary optional columns in the column chooser (that is what the last menu item adds). The FilterNode builder keeps filtering by column name, so composites are display-only and filters are untouched.

Click-to-expand a composite into its sub-columns was considered and left out: it needs per-user expand state, width recalculation and a colmodel that differs from the export, for the same outcome as adding the raw column.
