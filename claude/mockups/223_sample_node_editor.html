2. Proposed — one picker, one tree chosen

Search for any of the four kinds of thing. The tree underneath is always the whole patient, and the radio on a row is the level: pick the patient, a specimen, an extraction or a single sample. Everything below the pick is read; everything else is dimmed but still there. Filters are global by default — PASS-only, AD/DP/GQ/PL, zygosity, allele frequency — because only PASS means the same thing in every VCF. Each VCF's own FILTER codes and threshold overrides live under its sample row, collapsed until you expand it.

  • 1One search box — a grouped select2 (see below). Whatever you pick, the tree shows its whole patient with that row selected.
  • 2The tree is the level control. Circle radios on patient / specimen / extraction rows, square on sample rows. Dimmed rows are not read. Excluded samples stay visible, struck through, with the reason.
  • 3Sample rows are collapsed by default. A row with anything set shows a blue summary (AD≥5 · DP≥20 · +LowDepth). Expand it for that VCF's own FILTER codes — PASS is greyed because it is the global setting — and its threshold overrides (placeholder = inherited global, bold blue = overridden, reset clears them).
  • 4Global filters apply to every VCF read: PASS-only, AD/DP/GQ/PL, zygosity, allele frequency. PASS is the one FILTER value every VCF shares, so it is the only FILTER setting at this level; a VCF with nothing under its row gets exactly these.
  • Semantics per VCF: records included are PASS (if global PASS is on) ∪ that VCF's ticked codes. No global PASS and nothing ticked means that VCF is unfiltered.
  • Templates with locked inputs render the same tree read-only (no search box, radios disabled); the global filters and per-row overrides stay editable.
  • The editor title badge shows the patient's pedigree glyph, and the title reads the level — matching the card.

3. Simpler alternative — segmented level + one autocomplete alt

If the tree is more than you want: replace the dropdown with a segmented control that switches the autocomplete URL client-side (no form resubmit), and keep the flat preview list. Same resolvers and endpoints underneath; only the editor template differs. Loses the "see the siblings" and "move a level in one click" properties.
